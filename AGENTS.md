# AGENTS.md

Shared rules for every coding agent on this repo (Claude Code, Codex, Antigravity). `CLAUDE.md` imports this file.

## Rules for Every Agent

- On startup, create your own git worktree and branch if you are not already in one. Name the branch after your module (for example app, engine, pipeline, or content) and put the worktree in a sibling folder such as ../project-worktrees/<module>. Check git worktree list and git branch first so you never reuse another agent's branch.
- Work only inside your own worktree and branch. Never check out main or another agent's branch.
- Only edit files in the paths you own. If you need a change elsewhere, ask the owner or the human lead.
- Never change files in /contracts without human approval.
- Never use git stash. Commit to your own branch instead.
- Never force push or rewrite shared history.
- Merge main into your branch and run the tests or the app before opening a merge request.
- Commit small and often with clear messages.
- Mark a task done on the task board when you finish it.
- If blocked for more than 10 minutes, say so instead of working around it with hacks.

## Project: Daily Commit

Five minute daily interview practice for CS students. Adaptive (Elo) lessons over two tracks: system design (curated) and debugging (generated by a verified bug pipeline). Full plan: `docs/PLAN.md`.

## Merging

- CI must pass on every PR (question validator, `pytest api engine pipeline`, `npm run build`). Main accepts PRs only: no direct pushes, no force pushes.
- Human approval is required only where `.github/CODEOWNERS` says so: `/contracts` (whole team agrees, Tim merges) and `/engine` (Rushi reviews against the vectors in `contracts/rating.md`). Every other PR merges once CI is green.
- PR body includes `Closes #<issue>` so the task closes itself.
- Before you sleep: leave a handoff note in your open PR (what is done, what is next, anything broken).
- Unattended overnight agent runs only get tasks with a clear pass/fail check (content that must validate, corpus functions with test tables). Nothing that touches integration.

Worktree setup (run from the main checkout):

```
git worktree list
git branch -a
git worktree add ../project-worktrees/<module> -b <module>
```

## Contracts (read before writing code)

- `contracts/question.schema.json` - the one question shape for both tracks
- `contracts/topics.json` - the 10 topic ids the engine rates
- `contracts/api.md` - every endpoint with example requests and responses
- `contracts/rating.md` - Elo formula, constants, test vectors, lesson selection
- `contracts/examples/questions.json` - one valid question per format; use as fixtures and mocks
- `contracts/validate.py` - run `python contracts/validate.py` before committing any content

Integration boundaries: the app talks to the API only through `contracts/api.md`. The pipeline and content owners hand questions to the backend only as JSON files under `/content` that pass `validate.py`. Nobody imports another module's code.

## Stack

- App: Vite + React + TypeScript + Tailwind, mobile first, installable PWA. No native builds.
- API: Python 3.12, FastAPI, SQLite (stdlib `sqlite3`), single file DB at `api/data/app.db` (gitignored).
- Pipeline: Python 3.12, stdlib `ast` for mutation. Corpus tests are tables of `(args, expected)`; the pipeline's own runner executes them in a subprocess with a 3 s timeout and writes `test_output` itself (never a traceback). Every mutation changes exactly one existing line.
- Deploy: one service on Railway with a persistent volume for SQLite. The API serves `app/dist` at `/`. Plan B: laptop + `cloudflared` tunnel. The server reloads content and resets the demo user on every boot.

## Conventions

- Python: type hints, `pytest`, no global state outside `api/db.py`.
- Never hand-edit generated files (`content/debugging/questions.json`). Change the pipeline and rebuild.
- Commit messages: `<module>: <what>` e.g. `engine: add placement endpoint`.
- One task per PR. PR title starts with the task ID, e.g. `C3 engine: lesson selection`.
